# 语义与关键词混合检索实现方案

状态：已实现（2026-10-21）。设计日期：2026-10-21。

## 1. 总体方案

采用 **SQLite FTS5/BM25 + Embedding 语义召回 + RRF 融合**。关键词与语义分别召回，
取候选并集后排序，支持找回没有字面重合的记忆。

- 关键词使用现有 NFC、大小写规范化、汉字拆字与相邻短语规则，标题/正文权重为 4/1。
- 向量存入 SQLite，由 Go 对过滤后的向量流式执行精确余弦检索，保持纯 Go 构建。
- 关键词索引随记忆事务同步更新；向量由独立后台 Worker 异步生成，过期向量不参与检索。
- 公开支持 `keyword/hybrid`，默认 keyword；不公开纯语义模式。
- 本方案不包含查询改写、LLM 重排、自动记忆合并或来源全文索引。

## 2. 模块与流程

```text
搜索请求
  ├─ FTS5 + 结构化过滤 → 关键词候选
  └─ 查询 Embedding → 结构化过滤 + 向量扫描 → 语义候选
          ↓
  候选合并 → 当前内容校验 → RRF → Top-K → 摘要和证据

记忆写入事务
  → 快照、版本、证据、FTS、内容哈希、向量任务
  → 提交
Embedding Worker
  → 领取任务 → 事务外调用模型 → 条件提交向量
```

| 模块 | 职责 |
| --- | --- |
| `internal/retrieval` | 查询计划、双路召回、过滤、RRF、结果与解释组装 |
| `internal/embedding` | 文档编码、配置标识、哈希、向量校验、后台任务编排 |
| `internal/model` | Embedding HTTP 适配器，与记忆提取适配器分开 |
| `internal/store/sqlite` | FTS、向量、任务和批量快照/证据读取 |
| `internal/memory` | 在记忆写入事务中维护搜索文档和派生索引 |
| `internal/runtime` | 配置、Provider、Worker 的组装与关闭 |

查询接口由 retrieval 定义，后台任务接口由 embedding 定义，存储层实现接口。
`memory.DocumentBuilder` 保持纯函数，不能在业务写入事务中调用模型。
`RelatedActive` 继续负责关键词上下文选择，公共混合检索不同时改变自动提取行为。

## 3. 文档与向量

每条当前记忆对应一个向量，输入模板固定：

```text
kind: preference
title: 饮食偏好
content: 用户偏好清淡饮食。
```

文档只做 NFC 和首尾空白清理，保留大小写、标点与内部空白；查询做同样规范化，
但不套文档模板。不能把拆字后的 FTS 文本送给 Embedding。

- `content_hash`：模板版本与实际文档字节的 SHA-256。标题、正文、kind 改变时更新；
  只补证据、归档或激活不重复生成向量。
- `profile_id`：模型版本、端点身份、维数和文档契约版本的配置指纹，不含凭据。
  服务使用一套 Embedding 配置，查询和文档必须属于同一 Profile。
- Provider 响应检查条数、序号、维数、有限值和非零范数；L2 归一化后以 little-endian
  float32 保存。查询向量同样处理，点积作为余弦相似度。
- `min_similarity` 按模型用相关/不相关样例校准，在语义候选入选前应用；不能用 RRF
  分数替代余弦阈值，也不能默认将最相近的若干条视为相关。
- 单条输入不分块。输入长度由模型端点负责拒绝；查询失败时保留关键词检索，文档任务
  记录脱敏错误码，不静默截断。

## 4. 存储与索引一致性

直接在搜索表定义中加入字段并定义向量、任务表：

| 表 | 字段与约束 |
| --- | --- |
| `memory_search_docs` | 增加非空 `content_hash`，由文档构造器生成 |
| `memory_embeddings` | `memory_id` 主键；`profile_id`、`content_hash`、`dimensions`、`vector`、`embedded_at` |
| `memory_embedding_jobs` | `memory_id` 主键；`profile_id`、`content_hash`、`status`、`attempts`、`next_attempt_at`、`error_code`、创建/更新时间 |

向量和任务通过外键关联搜索文档，删除搜索文档时级联清理。维数必须大于 0，BLOB
长度为 `dimensions*4`；任务状态为 queued/running/failed，按状态、重试时间、创建
时间和记忆 ID 建领取索引。不增加 Profile 生命周期表。

`SearchDocument` 携带内容哈希。`sqlite.Tx.UpsertSearchDocument` 在同一事务中：

1. 更新 FTS 文档及哈希；输入变化时删除旧向量，并 upsert 最新的 Embedding 任务。
2. 新任务重置尝试次数；输入未变且已有有效向量时直接复用。
3. 输入未变、缺少有效向量且没有任务时补任务；不能重置已有任务的尝试次数或重试时间。

功能关闭时不调用模型或创建任务，但仍维护哈希和清除过期向量。开启功能或重建索引时，
扫描当前未删除记忆，为缺失或配置不匹配的向量补任务；failed 任务在下次启动补任务时
重排。任务通过数据库持久化，不能仅靠内存通知。

| 记忆操作 | 索引处理 |
| --- | --- |
| 创建、修改标题/正文/kind、恢复历史内容 | 按当前输入哈希判断复用或失效重建 |
| 补证据、归档、激活 | 输入不变则复用，查询按当前状态过滤 |
| 逻辑删除、永久清除 | 删除搜索文档及向量、任务；在途结果不能重新插入 |
| 清除来源原文 | 保留已提炼记忆的现有语义；不额外索引来源原文 |

FTS 重建按记忆 ID 更新文档并清理无效项，不通过清空搜索文档无故级联删除向量。
向量重建只生成后台任务，不在重建事务内等待模型，也不把已排队报告为已完成。

## 5. Embedding Worker

独立 Worker 并发为 1，与提取 Worker 分开。每个任务按以下顺序处理：

1. 短事务领取到期任务并增加 attempts。
2. 读取当前快照、构造输入并校验哈希；内容已变或删除时丢弃此次工作。
3. 在事务外调用模型并校验、归一化向量。
4. 短事务核对任务仍属于相同 Profile/哈希、搜索文档仍存在；条件成立才写入向量并
   删除任务。条件不符时不能修改另一代任务。

内容哈希和配置标识必须共同检查；旧代际任务在输入变化时同步删除，迟到的调用不能
把过期向量写回当前文档。

临时网络/5xx/429 最多尝试 3 次，指数退避从 1s 起、上限 60s 并加抖动，
429 尊重有上限的 Retry-After。鉴权、维数和协议错误直接失败，只保存脱敏错误码。
启动时恢复过期 running 任务，保留尝试次数。关闭服务时取消模型调用，未完成任务可恢复。

## 6. 查询与排序

1. 校验 mode、query 和过滤条件。空白/纯标点返回空数组，不调用模型。
2. 默认 `top_k=20`，非正值取默认值，超过 100 返回 `400`。每路候选数为
   `min(500, max(100, 5*top_k))`。
3. keyword 只查 FTS；hybrid 并行执行关键词查询和“查询向量→向量扫描”链路。
4. 两路应用相同的类型、状态、应用和更新时间过滤，默认仅 active，可显式查 archived，
   永不返回 deleted。`match=all/any` 仅控制关键词路，默认 any；keyword 模式的 any 会过滤
   受控停用词并要求至少一半有效词项命中，显式 all 才要求全部原始词项。
5. 向量 SQL 关联当前记忆和搜索文档，先过滤再流式计算，只接受 Profile、维数、内容
   哈希匹配的向量；以固定大小堆选候选，及时响应 context 取消。
6. 候选按 memory_id 合并，批量读取当前快照，排除已删除、过滤不符或输入已变的候选，
   再在各路连续编号并融合。

```text
score = 1 / (60 + keyword_rank) + 1 / (60 + semantic_rank)
```

rank 从 1 开始，未被某路召回时该路贡献为 0。关键词路按 BM25 升序，语义路按
余弦降序；同分按 updated_at 降序、ID 升序。融合结果按 score 降序，再按同样规则消歧。
不将 BM25 和余弦直接相加。

最终使用短只读事务校验快照并读取 Top-K 当前版本证据；模型等待和全量向量扫描在
该事务外。候选并发变化时允许不足 Top-K，不无限补查。
摘要来自原文；仅语义命中的结果 `matched_terms=[]`，不能伪造关键词命中。

## 7. 请求、响应与降级

接口：`POST /v1/memories/search`。

| 请求字段 | 约定 |
| --- | --- |
| `query` | 查询文本 |
| `mode` | keyword/hybrid，默认 keyword；其他值返回 `400` |
| `match` | all/any，默认 any，仅作用于关键词路；keyword 模式显式 all 为严格合取 |
| `filters` | kinds、states、created_by_app、updated_after、updated_before |
| `top_k` | 默认 20，上限 100 |
| `explain` | 默认 false，按需返回排序解释 |

```json
{"query":"吃饭有什么忌口","mode":"hybrid","top_k":10}
```

两种模式使用统一响应结构：

```json
{
  "items": [],
  "retrieval": {"mode":"hybrid"}
}
```

每项返回 `memory`、`score`、`snippet`、`matched_terms`、`evidence_refs`。
`retrieval.mode` 表示实际执行策略，不由某路是否恰好返回空集合决定。
keyword 模式的 any 查询 `score` 为 BM25 名次与词项覆盖率的融合分数，显式 all 为 -BM25；
hybrid 为 RRF。分数越大越好，仅用于当前结果排序。

`explain=true` 时返回 `explanation`：包含 `ranking`（bm25/rrf），以及参与的
`keyword: {rank, bm25}`、`semantic: {rank, cosine}`。不返回 Profile、内容哈希、
融合参数或逐项贡献。

| 情形 | 行为 |
| --- | --- |
| 语义功能关闭、无配置、模型网络/协议错误或 429 | 返回关键词结果，mode=keyword，warnings=[semantic_unavailable] |
| 查询模型超时 | 返回关键词结果，mode=keyword，warnings=[semantic_timeout] |
| 没有有效向量索引 | 正常执行 hybrid，仅返回关键词候选，不额外告警 |
| 部分向量未生成或失败 | 使用已有有效向量，mode=hybrid，允许少于 Top-K |
| 有有效索引但过滤后无候选或相似度不足 | 正常执行，mode=hybrid，允许空结果 |
| SQLite 错误 | 返回服务错误，不伪装成成功降级 |
| 父请求取消 | 取消两路，停止模型调用与扫描 |

`warnings` 仅在需要时出现，使用去重的稳定代码，不含提供商原始错误。
降级使用关键词原始分数和解释，即使 items 为空也保留实际模式与告警。
正常异步更新不逐次告警，索引失败和积压通过内部状态诊断。

## 8. 配置与调用边界

新增 `embedding` 配置：enabled、端点、模型版本、独立凭据、维数、调用超时和相似度
阈值。默认 disabled。在线查询使用固定的 500ms 子预算，不单独暴露并发或检索预算
配置；子预算到期只取消语义链路，仍返回关键词结果。

在线查询不自动重试。索引调用与在线调用使用不同路径；后台索引有固定重试预算，
不会占用查询请求的等待时间。
服务就绪检查只依赖本地服务与数据库，模型故障通过检索降级表达。

仅向模型发送当前记忆文本或当前查询，不发送原始来源、历史证据、整库和本地请求头。
日志不记录查询、正文、向量、完整模型响应或凭据；数据库派生数据沿用现有文件权限。
测试使用本地假服务，不依赖真实凭据；本方案不增加向量缓存。

## 9. 实施与验证

| 步骤 | 交付 |
| --- | --- |
| 1. 文档与类型 | 固定查询/响应契约；实现编码、哈希、配置指纹、向量校验及 RRF |
| 2. 持久化 | 修改建表定义，实现向量/任务仓储、原子失效、条件提交及重建 |
| 3. 模型链路 | 实现 Embedding 适配器、Worker、重试/恢复与 runtime 组装 |
| 4. 查询链路 | 实现向量扫描、双路并行、批量读取、摘要/解释和 HTTP 降级 |
| 5. 验证 | 执行确定性测试，比较真实模型下的关键词、纯语义与混合检索效果 |

验证重点：

- 哈希与输入一致；补证据/状态变化复用向量；非法、零或维数不符向量被拒绝。
- 写入与任务同事务回滚；内容更新、A→B→A、删除、崩溃恢复时旧结果不能覆盖新任务。
- 两路过滤一致，过期向量和 deleted 不参与；RRF 去重、单路贡献及稳定排序正确。
- FTS 重建不无故删除向量；纯语义命中不伪造 matched_terms；证据与快照版本一致。
- 模型超时、协议错误、空索引、数据库错误和请求取消的响应及资源释放正确。
- 用同义表达、无字面重合、中英文、精确实体、否定和无关查询评测 Recall@20、MRR@10、
  nDCG@10 与误召回率。假向量验证流程，真实模型验证效果，语义相似不作为事实一致或
  自动覆盖记忆的依据。

参考：SQLite 官方《FTS5》5.1.1 节；Cormack 等，SIGIR 2009，
《Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods》。
