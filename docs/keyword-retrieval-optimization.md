# 关键词检索优化实施方案

状态：第 2、3、4.1、4.2、4.3、5 节已实施；4.4 松弛合取在 LoCoMo 双语子集复评中未通过，已于 2026-10-22 移除。默认关键词路径不做硬性最低命中过滤；移除后的检索复评见第 9 节，端到端 QA 复评待补做。日期：2026-10-22。

## 1. 实施范围

- 只优化关键词检索，向量和混合检索保持关闭，不配置 Embedding Provider，不生成或重建向量。
- 保留 `match`、`kind`、`filters.kinds`、evidence 及其版本关联，不修改数据库结构和抽取协议。
- 不引入自动 kind 路由、kind 优先排序或 evidence 重排。
- 不将 evidence quote 或来源全文加入默认索引。
- 不引入 LLM 或 cross-encoder 重排。

## 2. 默认匹配方式调整

### 2.1 修改 match 归一化

调整 `internal/retrieval/query.go` 中的 `normalizeMatch`，默认使用 `any`，仅显式传入
`all` 时使用严格合取。

| 请求值 | 目标行为 |
| --- | --- |
| 缺失、空值 | `any` |
| `any` | `any` |
| `all` | `all` |
| 未知字符串 | `any` |

保持查询编译中的引号、转义和 SQL 参数绑定，不开放原始 FTS 表达式。
不增加自动匹配模式，也不增加 `all` 无结果时自动改用 `any` 的隐藏回退。

### 2.2 调用方式调整

- 普通自然语言查询省略 match，使用默认 `any`。
- 需要所有分词同时出现的短关键词查询，显式指定 `match=all`。
- 依赖旧默认合取行为的调用方，在升级前显式传入 `all`。
- 保持默认 `mode=keyword`、`top_k=20` 和现有生命周期过滤规则。
- 后台 `RelatedActive` 保持现有显式 `any` 调用，不同时改变抽取上下文选择逻辑。

## 3. 检索规则精简

### 3.1 kind 使用方式

- 保留 `memory.kind`，继续用于分类展示和管理。
- 保留 `filters.kinds`，仅在调用方明确限定类型时传入。
- 不根据问题中的时间、偏好等线索自动添加 kind 过滤。
- 不按 event、fact、preference、procedure 设置默认排序优先级。
- 不修改抽取阶段的 kind 输出和现有存储字段。

### 3.2 evidence 使用方式

- 保留 evidence 数据、`revision_evidence` 及当前版本的引用关系。
- 搜索结果继续返回轻量 evidence refs，原文通过既有接口按需读取。
- 保持证据合并、历史版本关联和来源原文清除流程。
- 不添加 evidence 存在优先、词面重叠优先、重叠加权或 quote BM25 重排。
- 不将 quote 拼接到标题、正文索引或每次回答的上下文中。

### 3.3 默认排序路径

```text
查询规范化和词典分词
  → 默认 any 编译，显式 all 保持合取
  → FTS5 检索与调用方显式过滤
  → BM25 排序
  → updated_at、id 平局排序
  → 当前快照、摘要和证据引用装配
```

不增加 session 去重或 session 优先展示分支，不为 kind/evidence 策略增加公开参数和开关。

## 4. 后续关键词优化

以下作为独立改动逐项推进，不与默认值调整一次性接入。先保持词典和索引结构不变，
后续排序特征只使用标题、正文与查询词项，不增加 kind/evidence 加分。

### 4.1 查询词项选择

1. 在查询侧增加词项选择步骤，置于分词去重之后、FTS 表达式编译之前。
2. 使用受控的中英停用词列表处理疑问词、辅助词和通用词。
3. 保留实体、数字、时间表达和否定词。
4. 移除后没有有效词项时，沿用原始分词结果，不生成无约束的全库查询。
5. 首先只作用于普通 `any` 查询；显式 `all` 和后台 `RelatedActive` 保持原有词项语义。

涉及模块：`internal/retrieval/normalize.go`、`internal/retrieval/service.go`。

### 4.2 标题与正文权重调整

1. 将标题/正文权重 4/1、2/1、1/1 作为候选设置，后续单独确定是否调整当前 4/1 默认值。
2. 权重继续由检索模块统一定义，由 SQLite 查询读取，不增加请求级权重参数。
3. 保持 BM25 后的更新时间和 ID 平局规则。
4. 不修改记忆原文、分词方式和索引表结构。

涉及模块：`internal/retrieval/types.go`、`internal/store/sqlite/search.go`。

### 4.3 词项覆盖重排

1. 在关键词候选召回与最终结果装配之间增加独立的候选重排步骤。
2. 计算每条候选在标题和正文中实际命中的有效查询词项及覆盖比例。
3. 使用有界权重将覆盖特征与原 BM25 排名融合，不直接相加原始 BM25 分数和覆盖率。
4. 不直接使用展示用 `matched_terms` 计算覆盖率，避免其回退逻辑影响实际命中计数。
5. 保持原始候选顺序作为稳定回退，不影响当前版本快照和 evidence refs 的一致性装配。

涉及模块：`internal/retrieval/service.go`，必要时增加内部重排模块，不扩展公开响应结构。

### 4.4 松弛合取（未采用）

原方案是在候选层按有效查询词项数实施“至少命中 N 项”。LoCoMo 双语子集复评显示该硬性
过滤会显著降低召回（见第 8 节），因此当前实现不采用：

1. 默认 keyword `any` 不设置最低命中数；FTS `any` 召回且通过显式过滤的候选全部进入覆盖率重排。
2. 保留显式 `match=all` 的严格合取语义，不新增公开 match 枚举。
3. 如需提高 precision，应优先使用软加权或按查询类型启用，不对候选做 `ceil(n/2)` 截断。
4. 重新引入前必须用独立检索基准验证召回不降，并补做端到端 QA 复评。

## 8. 检索效果复评（2026-10-22，bilingual-006）

数据集：`/home/ut005426@uos/data/locomo/bilingual-subset`，复用 `bilingual-003` 冻结的
500 条 active 记忆与 evidence，仅重跑检索；索引未重建，未重新抽取，未重跑 QA。基线为
`bilingual-003`（`adbc2c7`，词典分词、`match=any`、无第 4 节优化）。

Session 级 @10、`raw` 原始问题、466 条非对抗查询（462 条有 gold session）：

| 版本 | hit | coverage | MRR | precision@10 | 空结果 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基线 `bilingual-003` | 91.13% | 87.17% | 73.40% | 17.12% | 0/462 |
| 优化后 `f66a8af` | 75.76% | 71.39% | 64.86% | 11.06% | 67/462 |
| 仅词项选择 + 覆盖重排（无松弛合取） | 92.21% | 88.11% | 73.95% | 17.19% | 0/462 |
| 松弛合取最低 2 项 | 87.01% | 83.81% | 71.59% | 15.32% | 23/462 |
| 松弛合取最低 3 项 | 63.42% | 60.99% | 57.00% | 9.13% | 124/462 |

结论：

1. 4.4 的 `ceil(n/2)` 硬性最低命中数是本次回退的主因。自然语言问题有效词项中位数为 5，
   通常要求命中 3 项；FTS `any` 召回的候选往往只命中 1–2 项，相关记忆在重排前即被过滤。
   82 条 hit@10 退化查询中，79 条的相关记忆不再出现在 top-30，而不是排序靠后。
2. 4.1 词项选择与 4.3 覆盖率重排单独或组合使用均未伤召回：组合后 hit +1.08pp
   （95% CI -1.08pp～+3.46pp）、coverage +0.94pp、MRR +0.55pp、precision +0.06pp，
   数值上小幅改善但未达统计显著。
3. `expanded` 长查询放大问题：hit 92.42% → 39.61%，253/462 条查询为空，说明过滤强度
   随有效词项数增长，不能用于自然语言或扩展查询。
4. 优化后 nDCG 从 56.17% 升到 64.05% 是返回条数减少导致的 IDCG 分母效应，不能视为排序改善。
5. 建议：默认关键词路径移除 4.4 的硬性最低命中过滤，保留 4.1 与 4.3；若仍需提高 precision，
   应使用软加权或按查询类型启用，而不是对候选做 `ceil(n/2)` 截断。重新引入前必须用独立
   检索基准验证召回不降，并补做端到端 QA 复评。

## 9. 移除硬性过滤后的检索复评（2026-10-22，bilingual-007）

数据集与口径同第 8 节：复用 `bilingual-003` 冻结的 500 条 active 记忆、evidence 和索引，
仅使用 `be6b8c0` 新二进制重跑检索；未重新抽取、未重建索引、未重跑 QA。`raw` 原始问题，
466 条非对抗查询，其中 462 条有 gold session。

| 版本 | hit@10 | coverage@10 | MRR@10 | precision@10 | 空结果 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基线 `bilingual-003` | 91.13% | 87.17% | 73.40% | 17.12% | 0/462 |
| 上一版 `f66a8af`（含 `ceil(n/2)`） | 75.76% | 71.39% | 64.86% | 11.06% | 67/462 |
| 当前 `be6b8c0`（移除过滤） | 92.21% | 88.11% | 73.95% | 17.19% | 0/462 |

配对统计（当前 vs 基线，Session @10）：

- hit 91.13% → 92.21%，+1.08pp，95% CI [-1.08pp, +3.46pp]；改善 16 条、退化 11 条，
  McNemar p = 0.44，未达统计显著。
- coverage +0.94pp，MRR +0.55pp，precision@10 +0.06pp（95% CI [-0.65pp, +0.78pp]）。
- Turn 级 hit@10 59.96% → 62.77%（+2.81pp），coverage +2.12pp，MRR +1.15pp。
- 当前与 `bilingual-006-relax-none`（minimum=1 消融）逐查询排名列表完全一致（0 条差异），
  说明 `be6b8c0` 只移除了过滤，没有引入其他召回变化。

结论：

1. 上一版的召回回退完全来自 `ceil(n/2)` 硬性最低命中过滤；移除后 Session hit@10 恢复并略高于基线。
2. 词项选择与覆盖率重排本身不伤召回，但 precision 基本持平，0.005 覆盖率权重没有带来明显精度收益。
3. @20/@30 分别略低于基线 1.73pp/1.30pp，覆盖率重排会把少量相关候选推后；主指标 @10 与 MRR 仍改善。
4. 当前默认关键词路径可保留；若后续要提高 precision，应使用软加权或按查询类型启用，不应恢复
   `ceil(n/2)` 截断。
5. 本复评只覆盖检索，不含端到端 QA；上线前仍需补做 QA 复评。
