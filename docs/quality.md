# 首版质量与容量验收记录

本文件记录首版的固定标注样例、离线可重复评估和一万条原子记忆容量实测，
不替代自动化测试。

结论边界：

- 离线套件验证服务对模型输出的解析、落库、来源引用、作用域边界、失效和确定性冲突规则，
  不证明真实模型的语义质量。
- 真实模型语义评估有独立入口，但本次没有凭据或可用模型，未执行；不记为通过。
- 容量只实测一万条原子记忆；十万条、持续负载、功耗、费用和 OS 多应用集成仍未验证。
- 单机一次性数据不是性能 SLA；文件大小包含 WAL，可能大于实际业务数据大小。

## 1. 固定标注样例

样例位于 `tests/quality/testdata/labeled.json`，四类共 19 个案例：

| 类别 | 数量 | 标注内容 |
| --- | ---: | --- |
| 分类 | 5 | 平面标签、大小写/空格/重复规范化、已有标签不重复调用模型、空标签、作用域保持 |
| 摘要 | 4 | 否定与条件保留、项目作用域边界、截断只覆盖局部、画像排除一次性事件 |
| 冲突 | 8 | 唯一存续成员、正文收敛、已知不重叠时间线、重叠矛盾、pending、三方冲突、未知边界、已否定成员 |
| Skill | 2 | 前置条件/停止条件/反例/项目边界、失败反馈引用、输入截断提示、无执行认证和脚本 |

案例同时记录模型回放输出和可检查约束。摘要/Skill 的约束采用固定必含词和禁止词，不是完整
语义证明；禁止词不能理解否定句，因此样例文本避免在否定句中复述被禁止的断言。

## 2. 离线可重复评估

```sh
make test-quality
```

执行结果（2026-10-22，Go 1.27.3，Linux amd64）：

| 类别 | 通过 | 误判 |
| --- | --- | --- |
| 分类 | 5/5 | 0 |
| 摘要 | 4/4 | 0 |
| 冲突 | 8/8 | 自动解为 open 0；应解仍 open 0 |
| Skill | 2/2 | 0 |

冲突样例直接调用生产确定性复查逻辑，覆盖 `choose`、`timeline` 和保持 `open`。它不调用
模型，因此“冲突误裁决为 0”只适用于这些固定成员集合，不证明真实世界没有漏检或误判。
分类、摘要和 Skill 使用样例中的固定模型回放，验证处理链路和标注约束；真实模型输出仍可能
不满足约束。

`make check` 会运行这个离线套件，不需要外网、真实模型或生产数据库。

低风险完成结果闭环由 `internal/runtime/services_test.go` 中的
`TestProductionExperienceAndSkillAssembly` 覆盖：提交应用报告的完成结果 → 生成经验案例 →
自动生成并启用限定作用域 Skill → 同一 recall 返回 experience/skill 分区 → 撤销结果 →
旧案例和 Skill 退出召回并由后台重算。该测试使用本地假模型，不把生成或自报成功包装成执行
认证，也不从 README 的命令推断已经执行成功。

## 4. 一万条容量实测

命令：

```sh
make test-capacity
# 等价于 DMEMD_CAPACITY=1 go test -count=1 -timeout=30m -v ./tests/capacity/...
```

测试使用临时真实 SQLite、生产记忆/搜索文档/派生 FTS 路径，不访问真实模型。场景：

1. 一个来源下写入 10,000 条原子记忆，分布在 100 个项目作用域、每个作用域 10 个主题；
   每个作用域的主题 00 为 procedure，其余为 fact。
2. 自动登记 10,000 个分类目标、1,000 个主题摘要、100 个作用域画像和 100 个 Skill 目标。
3. 后台顺序处理 11,200 个治理任务；同时由独立读协程持续执行默认全层召回。
4. 全部任务收敛后执行一次来源永久遗忘，展开并清除 10,000 条记忆和 1,200 个派生对象。
5. 检查业务表清空、完整性检查为 `ok`，且清除后召回为空。

环境：Intel Core i7-10700（16 逻辑 CPU），31 GiB 内存，Linux 4.19 amd64，
Go 1.27.3，`CGO_ENABLED=0` 构建使用的 SQLite 驱动；工作区基于提交 `1d62860` 及质量与容量测试改动。

实测结果：

| 指标 | 结果 |
| --- | ---: |
| 写入 10,000 条原子记忆 | 9.9 s |
| 种子后数据库文件（含 WAL） | 28,130,864 B（约 26.8 MiB） |
| 初始治理积压 | 11,200 queued |
| 处理 11,200 个治理任务 | 1 min 57.6 s |
| 治理终态 | 11,200 succeeded；queued/running/waiting/failed 均为 0 |
| 并发默认召回次数 | 2,148 次，错误 0 |
| 并发召回延迟 | P50 45.0 ms，P95 55.9 ms，最大 75.2 ms |
| 收敛后 active 派生对象 | 1,200（1,000 摘要 + 100 画像 + 100 Skill） |
| 收敛后数据库文件（含 WAL） | 35,241,520 B（约 33.6 MiB） |
| Go HeapAlloc（测试进程） | 183.6 MiB |
| 单事务永久遗忘 10,000 条记忆 | 8.8 s |
| 遗忘后业务表残留 | 0 行（记忆、历史、证据、派生、FTS、来源、ingest 任务） |
| 遗忘后治理目标 | 10,000 cancelled + 1,200 queued |
| `PRAGMA integrity_check` | `ok` |

说明：

- 遗忘后的 1,200 个 queued 目标是已删除摘要/画像/Skill 的修复目标。它们只含目标键，不含
  原文；后续 Worker 没有可用输入时只会停用对象，不能恢复已删除正文或历史。
- 单事务清理耗时包含 10,000 次记忆清除、依赖枚举和派生对象删除。它已验证首版规模下的
  最坏扇出行为，但不代表更大闭包仍能在一个事务内完成。
- 并发召回期间 SQLite WAL 继续提供一致快照；测试没有观察到底层读错误。延迟包含关键词
  召回、派生 FTS 和分区组装，不含真实 Embedding 或真实模型调用。
- 文件大小不是压缩后大小，也没有在遗忘后执行 `VACUUM`。清理后的文件仍可能保留已释放页和
  WAL 空间，这不代表业务记录仍可读取。

## 5. 未覆盖范围与后续工作

- 十万条原子记忆、长期运行、并发应用、磁盘接近写满、进程反复崩溃和恢复时间未实测。
- 真实模型质量、费用、token、P50/P95 模型耗时和提示词版本评估未执行。
- OS 应用身份、沙箱、Unix socket、备份恢复、外部副本撤销和取证级擦除不在首版。
- 自动冲突复查只覆盖固定确定性规则；未知边界、多成员重新归组、语义漏检仍保持 open 或等待
  新证据。
- 这些缺口在本文件中保留为未通过，不用自动化测试数量或生成 Skill 数量替代。

## 6. 记录规则

- 只有实际执行的命令和可复查输出才写入通过结果；未执行的真实模型评估保持“未执行”。
- 容量结果必须同时记录环境、数据规模、命令和数据库文件口径。
- 模型语义质量报告至少记录模型/提示词版本、样本版本、每类通过率、错误样例和调用成本；
  本文件当前只记录离线契约评估。
