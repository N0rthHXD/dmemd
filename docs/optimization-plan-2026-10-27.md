## 1. 目标与边界

### 1.1 核心目标

使服务能够持续、可靠地完成以下闭环：

**从任意受支持的来源中保真记住有用信息 → 正确表达主体、条件和时间 → 保留演化历史 → 在合适的作用域下召回完整依据 → 生成可信、可更新的派生知识。**

优化顺序不是“哪个模块分低就先增加哪个模块的模型调用”，而是：

1. 先消除协议波动造成的信息损失，并让损失可见；
2. 再保证记忆的类型、时间、归属和更新语义正确；
3. 然后改善冲突收敛、关联召回和派生质量；
4. 最后在保持事实保真、来源可追溯和生命周期约束的前提下降低成本、延迟和长期维护负担。

### 1.2 明确不做

- 不修改外部评测数据、gold、评分脚本或报告来实现“提升”。
- 不硬编码报告中的人名、项目名、场景编号、查询或期望词串。
- 不为了适配一对一评分而把多个独立事实拼回一条记忆。
- 不通过放宽 scope、kind、生命周期或时间过滤来制造召回率。
- 不通过“最后写入者获胜”或强制 accepted 提高冲突裁决数量。
- 不把词项同时出现、引用结构合法、模型自报覆盖完整等同于语义正确。
- 不把派生对象数量、Skill 激活数量或任务 succeeded 数量当作能力指标。
- 不包含测试建设、评测执行、验收指标、质量门禁或压力验证等工作模块。
- 本次只形成方案，不修改运行代码，不调用真实模型，不重跑评测，不变更现有数据库。

### 1.3 保持的架构约束

继续采用本地 Go 单进程、SQLite、异步摄取、独立治理与 Embedding Worker；保持统一 any 关键词语义、事务性写入、不可变历史、来源追踪、同步失效和永久遗忘闭包。不引入外部向量数据库、全量知识图谱平台或多 Agent 编排作为前置条件。

`scope_key` 继续是组织和检索边界，不包装成身份认证或安全权限。服务接受一条来源断言，不代表独立验证了现实世界中的真实性。

### 1.4 未发布阶段的实现约束

- 接口、模型协议和内部数据结构直接按目标设计修改，不考虑旧接口兼容。
- 删除被替代的字段、协议和实现分支，不保留兼容适配、双写或过渡版本。
- 直接修改初始化 schema，不设计旧库迁移、历史回填或兼容读取；后续开发使用新数据库。
- 接口与数据结构变更同步更新 OpenAPI、README 和契约文档。
- 上述是后续实现约束，不意味着本次修改方案会删除或重建现有数据库。

## 3. 总体处理链路

```text
原始来源（保持原样）
  → 服务端来源视图：稳定片段 ID、原文位置、角色、可用时间上下文
  → 结构化提取：独立断言、类型、语义限定、证据、更新意图
  → 安全形状规范化
  → 分级校验：硬错误 / 可修复错误 / 质量疑点
  → 仅对必要候选定向修复，保留已通过候选
  → 事实身份查找 + 同作用域相关上下文 + 组内时间线
  → 确定性处理优先，歧义部分交给决策模型
  → 单事务提交：原子、证据、历史、关系、冲突、索引、任务质量结果
  → 按资格和影响范围调度治理
  → 原子召回 + 有界关联展开 + 来源可追踪的派生分区
```

贯穿全链路的约束：证据不能靠 repair 编造；质量疑点不能自动变成“没有可记内容”；任何派生文本都不能倒灌成独立原子事实；删除和取消必须阻止迟到结果恢复内容。

## 4. P0-A：输入可靠性、协议容错与质量结果

### 4.1 服务端来源视图

- 在 `source` 模块构建确定性的模型输入视图，不修改客户端提交的原始 JSON。
- 对消息、纯文本和结构化字符串字段分配 source 内唯一的 `segment_id`；保存或确定性重建其到原始字段路径、rune 范围的映射。
- 保留客户端消息 ID 作为辅助信息；缺失、重复或与内部 ID 重名时，内部定位仍然唯一。相同 source 重试时映射稳定。
- 提取与 repair 使用同一视图，模型只引用可见片段 ID。未知 ID 不通过模糊匹配“修正”；只有原文精确唯一定位时才允许恢复缺失引用，并记录恢复方式。
- 长文本中重复出现同一句话不能取第一个位置猜测主体；多片段联合证据必须分别定位。
- 保留消息角色和报告归属。助手建议、引用文本、假设和用户确认分开表达，不能把“建议限制甜食”直接升级为“用户已采用该习惯”。角色是来源信息，不是身份认证。

### 4.2 明确协议及无损规范化

为模型协议提供版本化的完整 JSON 示例/结构定义；支持 JSON Schema 的 Provider 可使用受约束输出，不支持时使用明确示例加本地校验。仅使用 `json_object` 不能视为字段类型已受约束。

安全规范化白名单：

| 字段 | 正式结构 | 允许恢复 | 不允许恢复 |
| --- | --- | --- | --- |
| `evidence` | 证据对象数组 | 单个合法证据对象 → 单元素数组；逐项诊断 | 任意字符串 → 编造 quote；无证据仍假装已验证 |
| `fact_group` | 单个对象或缺省 | 单元素对象数组 → 对象，且字段合法 | 多个组任选一个；把正常对象变成数组 |
| `procedure` | 单个对象或缺省 | 单元素对象数组 → 对象，且字段合法 | 无关文字 → 伪造流程结构 |
| `procedure.steps` 等列表 | 字符串数组 | 单个非空字符串 → 单元素数组 | 按标点随意切分、重排步骤或补齐缺失分支 |

保留规范化记录；字段类型错误不能在解析时静默变为“缺省”。部分证据非法时只剔除该项，但剩余证据必须足以支持候选的完整断言，否则仍需 repair/隔离。

### 4.3 分级校验，而非宽松入库

| 等级 | 例子 | 处理 |
| --- | --- | --- |
| 硬边界 | 原文禁止保存、伪造引用、越权 scope、不可定位证据、非法时间区间 | 禁止作为已通过候选入库；隐私排除不可通过 repair 复活 |
| 可修复协议问题 | 安全形状变化、非法枚举、必要字段缺失 | 先确定性规范化，再对问题候选使用有预算的 repair |
| 语义质量疑点 | 日期等价写法、引文含否定但断言已正确表达、流程被忠实改写 | 不再仅凭子串/否定词存在性直接判丢失；结合断言所指及结构信息做定向复核 |

特别调整现有三类过强校验：

1. 日期由规范化后的语义值和精度比较，不要求原文日期字符串在正文逐字出现。
2. 否定校验针对被提取的断言，而不是“整段引文有一个不字，所有候选正文都必须带不字”。
3. procedure 结构保留顺序和条件，但不要求结构字段在正文重复一遍同样的字符串。

不能把“降级”理解为删除关键数量、否定、条件或时间以绕过校验；无法消除的语义风险明确隔离。

### 4.4 候选修复与任务质量结果

- 已通过候选不进入 repair，结果保持不变；只修复错误候选。候选及拆分子候选有稳定 lineage，repair 的关联键由服务控制。
- 默认每次尝试最多一次模型 repair，先用无需模型的恢复降低调用量；达到预算后返回明确质量结果，不盲目增加重试次数。
- repair 超时与无效输出分别记录；坏候选的 repair 失败不应抹掉已经安全通过的候选。整个处理预算耗尽、事务失败仍按任务失败处理。
- 保留现有 job 调度状态，另外增加 `quality_outcome` 和分阶段统计，避免把业务质量塞进调度枚举。

| 情况 | 调度状态/质量结果 |
| --- | --- |
| 合法空提取 | `succeeded` + `empty`，仅表示模型未选出候选，不宣称已证明没有有用信息 |
| 候选全部安全处理，包括重复补证或明确 skip | `succeeded` + `complete`；统计动作，区分没有新增和没有提取 |
| 保留部分候选，同时有无法恢复的候选 | `succeeded` + `partial`；返回隔离数量、固定错误码和阶段 |
| 非空候选全部因协议/证据错误不可用 | 按既有有界协议重试进入 `waiting/failed`，质量结果 `unusable`，不得伪装成正常空结果 |
| 内容全部因明确隐私排除而不保存 | 正常完成，记录排除原因；不得通过后续自动重试重新提取 |

诊断包含 candidate ID、field、code、normalize/repair 状态和最终处置，不含原文或完整模型响应。统计区分原始候选、拆分后候选及各阶段数量，避免 repair 和拆分导致重复计数。隔离只保存诊断，不新增一份绕过遗忘机制的原文/模型输出仓库。

**主要改动位置**：`internal/source/`、`internal/model/{protocol,parse}.go`、`internal/ingest/{types,extraction,processor}.go`、job 持久化、HTTP DTO 与 `api/openapi.yaml`。

## 5. P0-B：提取保真度、类型和时间语义

### 5.1 按“可独立更新”定义原子，不按字数拆分

- 独立变化的属性分别保存；同一断言不可缺少的主体、对象、正反偏好、数量、单位、地点、适用条件和否定必须一起保留。
- “不喜欢某种方式，更喜欢另一种方式”可以是两个断言，但需要关联，召回时不能只展示一半并假装表达了全部偏好。
- “某人在某学校读二年级”不能只记住年级并丢掉学校；必要限定不是可随意删除的背景。
- 流程的依赖步骤构成可复用单元，不为了原子化把每一步拆到无法还原顺序；目标、流程和一次执行结果仍分开。
- 保留“可能、据说、某人认为”等不确定性和转述归属；`accepted` 表示服务采纳了带限定的来源断言，不代表断言已被独立验证，也不能用 pending 混代所有不确定表达。
- 增加通用的限定槽位/质量检查，重点检查实体、值与单位、条件、极性和归属。不建立报告关键词清单，也不把同一会话所有词项拼接当作事实恢复。

### 5.2 类型语义一致性

| 类型 | 判定标准 | 常见边界 |
| --- | --- | --- |
| fact | 可持续成立的状态、属性或明确归属的观测断言 | 一次测量可以是带观测时间的 fact，不自动推广成长期健康状态 |
| preference | 喜好、要求、默认行为及强弱约束 | “必须”“希望”“不再要求”必须保留强度和条件 |
| event | 一次发生、计划、发布、取消或阶段变化 | 已发生的单次活动不因有动作而成为 procedure |
| procedure | 可复用的条件—动作/步骤—完成或停止检查 | 不要求原文拥有所有可选字段；缺失条件记 unknown，不由模型补造 |

用 `phase`、`durability`、流程结构等检查与 kind 的矛盾；缺失 kind 不再无诊断地默认为 fact。先通过提取或定向修复解决，不让检索器忽略 kind 过滤“补救”。

将 `procedure` 从仅存在于候选的临时结构升级为原子修订中的可选结构化内容，纳入版本、hash、失效、导出和遗忘闭包；保留可读正文，但治理不必从正文重新猜步骤。

### 5.3 区分三种时间，避免“有日期就填有效起点”

1. **记录时间**：服务何时接收/保存该断言，由服务生成。
2. **陈述/观测/事件时间**：来源何时作出陈述、观测或计划事件发生的时间，分别记录依据，不能与接收时间混用。
3. **事实有效时间**：某个状态从何时到何时成立，沿用半开区间语义；不能把正文提到的所有日期都作为边界。

现有 `observed_at` 同时存在协议和回退语义，实施时统一其定义，并显式标记时间依据；不能再把来源接收时间回退值当成“新事实发生得更晚”的证据。

时间处理要求：

- 提取日期所修饰的对象及其语义角色，再决定是否填写有效区间或事件时间。
- 保留日期原文、精度、时区及推断依据。只有日期无时区时，不伪造一个“明确 UTC 零点”；只有月份时不伪造某一天。
- 相对时间优先基于同消息的可信时间上下文解析；无上下文时保持未知，不因服务今天收到历史会话就把“明天”解析成明天。
- 状态更新关闭旧有效区间；错误更正另走纠错语义；计划事件使用事件时间和 phase，不因未来 `valid_from` 被当前查询完全隐藏。
- “现在有哪些未来安排”按计划知识的有效性查询；“某时点发生了什么”按事件时间查询，两者不混用。明确 API 过滤含义后再落地。
- `as_of` 定义为事实有效时点查询，不自动等价于“当时系统知道什么”。后者需要额外记录时间截面，列为后续能力，不在本轮暗中承诺。
- 已知不适用于查询时点的事实必须排除；时间未知的结果必须标记不确定，显式历史查询默认不把无法证明时间适用的事件当作确定答案。

**主要改动位置**：提取协议与校验、`internal/memory/{types,rules}.go`、原子修订存储、`internal/retrieval/` 和 SQLite 时间过滤；新增有界的通用时间解析/归一化模块。

## 6. P0-C：事实身份、历史演化与冲突收敛

### 6.1 先找到同一事实，再讨论是否矛盾

- 事实身份至少包含显式 `scope_key`、主体、谓词及必要条件。现有事实组查找主要依赖 subject/predicate/scope 文本精确一致，需要加入明确的作用域约束和查找路径。
- 先做同作用域的规范化身份查找和组内时间线读取，再用关键词/向量补充相关上下文；不能完全依赖新值正文能否召回旧值。
- 主体/谓词别名按作用域维护；只做有证据的等价关联。不同家庭成员、不同项目和不同检查项目不能因文本近似合并。
- “同一事实的多个版本”与“同一叙事下的多个事实”分开建模：`fact_group` 用于同一属性/断言槽位的演化；另设有证据的上下文关联，不能把整段叙事塞进 single 事实组。
- 上下文完整性从全 source 一个布尔值收敛到候选/事实组级：某个无关组被截断，不应把其他完整组的安全更新全部降为 pending。

### 6.2 明确区分变化、纠错、独立观测和真正冲突

| 情况 | 应有行为 |
| --- | --- |
| 相同事实再次出现 | 补充证据，不产生互相竞争的当前值 |
| 状态从某时点发生变化 | 保留旧值历史段，创建后继，写 `supersedes` 和演化审计 |
| 明确说明过去记录错误 | 保留原错误版本和更正证据，拒绝错误断言；不伪造它曾真实有效的时间线 |
| 不同时间的独立测量/检查 | 分别保留观测时间；数值不同本身不构成冲突，不把正常变化一律当成纠错 |
| 同一事件改期/取消 | 根据事件身份关联原计划和新阶段，不把旧时间当成当前计划 |
| 同条件同有效区间、互斥值且无法判定 | 创建 open 冲突和明确的 pending 候选，等待新证据或显式裁决 |
| 不同主体、场景、条件或可并存多值 | 保持独立，不制造冲突 |

自动收敛必须同时具备：同一事实身份、适用的单值语义、可定位的完整更新证据、足够时间/更正依据和完整的相关成员集合。不能仅依赖模型的 action/reason、自报置信度或接收顺序。

### 6.3 补全触发条件和审计

- 更新证据同时保留“替换/更正/不再要求”等语义及新值，不只引用新值短语。
- 同一 source 多次提到同一属性时，先按来源语义整理有序演化链；不能因为同组存在两个候选就永久禁止收敛，也不能用 candidate ID 字典序代替事实顺序。
- 对每次未自动收敛输出固定原因，如 `identity_ambiguous`、`missing_update_evidence`、`time_unknown`、`cardinality_unknown`、`context_truncated`。
- 原子、前驱状态、关系、成员版本和裁决审计同事务提交；保留当前乐观版本校验与 409 行为。
- 已创建的冲突在裁决后保留 resolved 记录。纯共存的时间线不为增加 resolved 数量而人为创建冲突，但同样保留演化审计。
- 继续 accepted 优先、pending 明确标记；检查最终 HTTP 响应及 `max_context_tokens` 裁剪，确保未决冲突提示不会随正文裁剪消失，且不会把待决内容包装成确定答案。

**主要改动位置**：`internal/ingest/{processor,convergence,merge}.go`、`internal/memory/conflicts.go`、`internal/governance/conflict.go`、`internal/store/sqlite/{groups,conflicts}.go`、相关上下文接口。

## 7. P1-A：完整召回与真实语义路径

### 7.1 保留关键词基线，补充有界关联召回

- 继续统一 any、BM25 与有界覆盖重排，不重新引入 all 或最低命中词数硬过滤。
- 先获得主命中，再按明确关联展开必要的偏好另一半、事件关键限定、流程条件或同事实的冲突成员；不展开整个会话。
- 关联展开必须保持同一查询的 scope、kind、state 和时间约束。超出调用方过滤的背景如确有必要，只能经明确的新契约进入独立、标记的上下文，不得混入合格主结果。
- 将同一事实的重复表述折叠为展示簇，保留每条依据；用有界多样性提高信息覆盖，不能通过去重删除否定、条件或时间不同的事实。
- 关联关系、结构化流程及所有新索引必须参与归档、失效和永久遗忘。

### 7.2 过滤诊断与解释

在 `explain=true` 或受限诊断入口增加阶段计数：词项候选、kind 排除、时间排除、状态排除、重排及预算裁剪。必要时只放宽一个过滤做同 scope、有界计数，不改变实际结果。

`kind_filter_excluded` 只能说明存在被排除的候选，不能单凭文本命中断言“模型分类错了”。诊断不返回跨作用域正文，不用全库无过滤查询解释空结果。沿用用户全局记忆继承语义时，也必须与正常查询保持一致。

### 7.3 Embedding 可用性与降级治理

- 提供显式的 Embedding 配置与连接诊断：端点、模型、维数、权限及响应合法性；区分配置错误、限流、超时和索引未就绪。
- 暴露文档向量覆盖率、待生成数、失败数和配置指纹一致性；没有当前向量时不能把空向量结果解释成语义不相关。
- 模型、维数或文档构造方式变化后，旧向量退出当前配置的召回，持久化登记重建任务；只使用与当前原子版本和内容 hash 一致的向量。
- 关键词与语义分支使用一致的 scope、kind、状态和时间约束；RRF 仅融合各自合格的候选，不绕过事实过滤。
- 保持关键词 fallback 与当前 500ms 在线预算，返回稳定的降级原因，不因语义服务不可用阻塞原子查询。

**主要改动位置**：`internal/retrieval/`、`internal/embedding/`、`internal/model/embedding.go`、搜索存储和诊断 API。

## 8. P1-B：派生目标、内容质量和 Skill 生命周期

### 8.1 作用域概览与 topic 解耦

新增通用 `scope_summary` 派生类型，归入 summary 召回分区；直接调整派生枚举、目标键和响应结构，不保留旧结构兼容分支。目标键由作用域与派生类型确定，不要求模型输出项目名称作为 topic。

- 作用域概览直接从同 scope 的合格原子综合现状、约束、关键历史和计划，避免用 Profile 承担项目进度摘要。
- 主题摘要保留为细分视图；父主题直接读取叶子原子，不引入摘要依赖摘要。
- 内置 taxonomy 只保留通用概念；未知业务实体成为作用域内扩展标签，不为报告里的项目新增内置项。
- 将别名、父子主题和实体关联分开；不把任意带 `/` 的字符串机械拆成层级。别名确认或修订触发旧/新目标失效。
- 摘要生成受输入差异和需求约束，相近且输入高度重复的目标合并调度，控制“一条事实多个标签、多份重复摘要”的膨胀。

### 8.2 把三种“完整”分开记录

1. **输入选择完整性**：共有多少合格原子、实际选入多少、因何截断，由服务确定。
2. **引用结构完整性**：所有引用是否真实存在、版本是否匹配、是否在允许输入中，由服务强制校验。
3. **正文语义覆盖与忠实度**：分别记录正文关键断言、限定条件、支持引用及省略内容；无法确定是否覆盖时标记未知，不用子串或模型自报直接认定完整。

生成结果增加段落/要点到 memory/version 的支持引用，以及被省略输入及原因。服务拒绝不存在的引用，但不把“引用合法”宣称为“引用足以支持正文”。

保留“全部生成输入”作为保守失效依赖，另记录“正文要点支持引用”；二者不能混淆。前者用于新鲜度和遗忘，后者用于解释内容依据。覆盖未知时使用 `unknown`，不靠在正文添加一句“仅覆盖部分”就视为质量达标。

摘要目标是忠实综合而非复制原子列表；一两条输入允许简短列举，不以排版形式单独判定质量。需要保留问题—措施—结果、条件—偏好、旧状态—变化—现状等真实关系，不由模型补造因果。

### 8.3 Profile 和 experience

- Profile 同时经过输入资格检查和生成内容检查；长期事实/偏好/约束与一次性活动、计划、进度分开。
- 对 durability 不确定的内容不自动提升为长期画像；跨时间重复出现可形成新的持久性判断，但需要来源依据，不能把重复模型输出当重复证据。
- Profile 保留健康等敏感断言的报告归属、不确定性和适用条件，不输出无依据的诊断结论。
- experience 保留应用报告语义；结构化 outcome 继续使用稳定枚举，展示文本按来源/请求语言渲染，不把 `success` 翻译为“成功”当作语义能力提升。
- 不为满足字面锚点强制全中文；专业术语、专名和原文语言优先保真。

### 8.4 Skill：先满足资格，再创建内容对象

- 移除摘要处理顺带为每个 topic 创建无内容 Skill 的行为。
- 调度前检查是否存在合格 procedure；没有输入时记录目标评估结果 `no_procedure_input`，而不是新建一个永远无 revision 的 artifact。
- 已经存在的 Skill 失去来源时仍立即 stale/disabled，保留历史和原因；不能通过“不再创建空对象”绕过旧内容失效。
- 按可复用工作流和适用边界组织 Skill，不按每个 topic 都生成一份。经验只能补充已报告的适用条件和反例，不能凭经验成功推导不存在的流程。
- 经验输入须有同工作流、显式 Skill 引用或有依据的适用条件关联；仅同 scope 不足以成为相关经验。改进当前 `loadSkillRuns` 按 scope 汇入结果的路径，避免一个工作流的成功/失败污染另一个 Skill。
- 输入明确给出的步骤、前置条件、停止条件、完成检查和失败分支必须保留；未知项明确未知，不为了补齐格式编造内容。
- 激活要求可用 revision、合法直接来源和内容检查通过；有正文不代表具备充分的工作流质量。继续保持指导文本、无执行授权、无成功认证。
- `no_input`、`topic_mismatch`、模型不可用、生成失败、输出不合格分开；无输入目标只有在输入变化时重评，避免周期性空转。

### 8.5 对象与目标状态可发现

直接整理 artifact 管理接口，统一详情、历史、列表及生成目标查询的结构：按 scope、kind、state、reason 过滤，使用有界游标；可区分 queued/running/waiting、无合格输入、生成失败、已有可用版本和 stale，不为旧响应结构保留适配层。

“尚未具备资格”和“存在失败的内容对象”分别展示。应用不再靠 recall 命中正文来判断对象是否存在，也不需要无限等待一个根本不会生成的对象。

**主要改动位置**：`internal/{topic,artifact,skill}/`、`internal/governance/{aggregate,skill,reconcile}.go`、`internal/store/sqlite/artifacts.go`、HTTP artifact 路由与契约。

## 9. P2：长期记忆质量与运行效率

### 9.1 有用性与噪声控制

- 显式“不保存”优先于任何记忆价值判断，继续保持不可修复复活和完整遗忘。
- 依据未来可用性、明确意图、事件重要性、适用期限和重复证据决定是否保留；不使用钓鱼、训练等领域词黑名单。
- 区分有价值的一次性事件与无后续用途的闲聊，不把 episodic 全部丢弃，也不把带情绪的叙述全部当重要事件。
- 增加保留理由/不保留理由固定类别；低价值判断同样会误删，必须同时观察噪声写入和有用信息漏记。
- 临时性影响展示和维护策略，不自动触发不可逆永久删除。自主清理和默认 TTL 另行评审，不扩大本轮授权。

### 9.2 模型成本、长输入与恢复

- 分别测量排队、提取、规范化、repair、上下文、决策、提交和治理耗时，以及每个有效原子的调用/token 成本。
- 优先减少可确定场景的决策调用；尤其改善多候选情况下仍逐批调用模型的可避免路径，但不得把空关键词结果当成全库确无相关事实。
- 拆分提取/决策与治理模型配置、思考策略和超时，允许按任务选择模型；不把关闭思考或更换快模型当成协议和语义问题的默认修复。
- 对超过单次处理能力的来源，以稳定片段做有界分块，保留跨块指代和重复消解；当前 64 候选上限先显式诊断，不能静默截断或仅无限增大上限。
- 若引入阶段检查点，保存版本化结构化中间结果而非完整模型响应；遵守来源清除、加密/权限和遗忘闭包。最终写入仍按 source 原子提交，取消和输入变化拒绝迟到结果。
- 保持 ingest 优先和治理合并；增加任务年龄、stale 持续时间及重试原因监测，防止长期摄取使治理永久饥饿。

本轮不顺带实施多租户、认证、外部备份或远端副本撤销；这些是独立产品和安全边界。

## 10. 运行诊断与可观测性

以下属于服务运行能力，用于让调用方理解处理结果和故障原因，不包含测试、评测或验收工作。

- 摄取漏斗：提取、规范化、校验、repair、隔离、隐私排除、skip、补证、pending、写入；按阶段、模型/协议版本、固定错误类别汇总。
- 质量结果：empty、complete、partial、unusable；技术性全丢和正常零新增分开。
- 时间/分类：kind 修复、时间依据未知、精度冲突及历史查询不确定结果。
- 演化：身份查找结果、相关上下文截断、未收敛原因、open 持续时间、自动裁决及人工撤销/更正。
- 派生：目标资格、输入覆盖、等待与失败原因、stale 持续时间、内容检查结果、引用完整性和重建耗时。
- 语义：当前向量覆盖率、索引积压、Embedding 错误类型、降级率及 fallback 结果。
- 资源：排队与各阶段耗时、模型调用/token、每条有效记忆成本、数据库和索引增长。

零记忆结果不自动视为故障：纯闲聊、明确排除和重复补证不需要被强制转换为新记忆，须通过处理原因区分。

指标标签不使用原文、查询、用户/项目名称或无限 candidate ID，避免隐私泄漏和高基数；局部诊断通过受限详情返回引用及固定错误码。

### 12.2 主要风险及防护

| --- | --- |
| 容错变成放松事实安全边界 | 只恢复白名单结构；证据、scope、隐私排除和区间硬边界不变 |
| 放松字符串校验后语义错误增加 | 保留结构化限定检查和来源依据，不把“解析成功”当作“事实正确” |
| 主体/谓词别名错误合并 | 作用域约束、证据关联、版本审计；歧义保持独立或未决 |
| 接收时间被当成真值顺序 | 区分记录/陈述/事件/有效时间；自动裁决拒绝仅靠接收顺序 |
| 新时间建模隐藏未来计划 | 分开处理计划知识有效性与事件发生时间，不用未来事件时间阻断当前安排查询 |
| 关联展开消耗预算或泄漏过滤外内容 | 有界展开、独立标记、过滤一致，优先保留冲突提示预算 |
| 摘要/Skill 数量膨胀与治理饥饿 | 输入资格、目标合并、输入签名去重、任务年龄监控和成本预算 |
| 新中间数据绕过删除闭包 | 只持久化必要结构；取消、清除、遗忘须覆盖新增数据并阻止迟到写入 |
| 模型差异导致协议或语义漂移 | 服务统一协议规范化、证据约束和固定诊断码，不依赖单一模型自报结果 |

## 13. 推荐的第一批实施范围

第一批只做 **M1**：

1. 缺失客户端消息 ID 时的服务端稳定来源定位；
2. 提取协议形状明确化与安全规范化；
3. 候选分级校验、局部 repair 和通过候选保护；
4. 全无效候选的非静默失败语义与候选级质量诊断。

这一批直接调整相关接口、协议、数据结构和初始化 schema，先让后续模块拿到可靠输入，并能准确说明“没有记忆是正常过滤、协议问题还是语义遗漏”。之后再实施时间/身份/冲突和派生优化，不增加兼容、迁移或验证测试工作包。
